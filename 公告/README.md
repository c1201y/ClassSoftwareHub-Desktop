# 公告

客户端首页顶部那几条横幅的正文就放在这里。**改完 push，用户下次启动自己就看到了**，不需要发版、不需要后端配合。

## 两个文件，按范围分工

| 文件 | 谁能看到 |
|---|---|
| `all.json` | 所有版本 |
| `1.2.0.json` | 1.2.0 这个发行版，以及它的预览版（`1.2.0-insider1.9` 也会读它） |

文件名就是筛选条件，客户端只认这两种。预览版的完整号（`1.2.0-insider1.9.json`）如果存在，优先级更高——只有确实只想给某一个预览构建看时才建它。

## 怎么写一条

直接一个数组。想发一条就往里加一个对象，不想发了就删掉那一条。

```json
[
  {
    "id": "2026-12-02-server-migration",
    "level": "warning",
    "title": "服务端将于 12 月 2 日迁移",
    "body": "12 月 2 日 22:00 起服务端迁移到新机房，期间约 30 分钟在线功能可能不可用。",
    "startsAt": "2026-11-20T00:00:00Z",
    "endsAt": "2026-12-03T00:00:00Z"
  }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一标识。用户关掉后按它记住，所以**同一条公告不要换 id**；真要重新提醒一次就换个新 id |
| `title` | 是 | 标题，一行 |
| `body` | 否 | 正文，自动换行 |
| `level` | 否 | `info`（默认）/ `success` / `warning` / `error`，决定图标和配色 |
| `startsAt` | 否 | 开始显示的时间（UTC）。不写 = 立即 |
| `endsAt` | 否 | 停止显示的时间（UTC）。不写 = 一直显示，直到从文件里删掉 |
| `dismissible` | — | **已停用**：公告一律没有关闭按钮，写了也不生效 |
| `link` | 否 | 点按钮跳转的地址（http/https） |
| `linkText` | 否 | 按钮文字，不写就是「查看详情」 |

## 几条约定

- **时间一律写 UTC**，末尾带 `Z`。写本地时间会被当成 UTC 处理，差 8 小时。
- 一条公告显示多条也没关系，按数组顺序从上往下排。
- **公告没有关闭按钮**：它到 `endsAt` 自己消失，或者你把它从文件里删掉。
  不给用户本地关闭，是因为那等于让同一件事在每台机器上各关一遍。
- 发出去之后想撤回，把那条从数组里删掉再 push 即可。
- 客户端有缓存：同一次运行里 10 分钟内不会重复拉，改完想马上看到效果就重启应用。
