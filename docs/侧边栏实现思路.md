# 侧边栏实现思路整理

> 2026-10-01 整理。用途：把「屏幕边缘侧边栏」这套东西的设计思路、模块划分、关键决策与已知约束收敛成一份可查阅的文档。铁律与踩坑史仍在记忆库 `TOPICS.md` §A，本文是其「为什么这样设计」的叙述版。

---

## 1. 要解决的问题

课堂场景：全屏放 PPT / 视频时够不到任务栏。所以要在**屏幕边缘**常驻一条可呼出的工具条：

- 收起 = 一小截圆角抓手（20×110 DIP，亚克力底），点一下展开，**按住可拖**着换位置、换边；
- 展开 = 工具面板（92×450）+ 底排五颗按钮（收起 / 常驻 / 位置复原 / 隐藏 / 打开应用）；
- 置顶、不进任务栏、无标题栏、不可缩放 —— 它是「贴在屏幕上的浮层」，不是普通窗口。

---

## 2. 总体架构：四层职责

```
┌─ 配置页层  Pages/SidebarLayoutPage（拖拽拼装 + 底排开关）
│
├─ 模块定义层  Data/SidebarModule.cs
│     SidebarModules.All（静态清单） + AppSettings.SidebarModuleIds（用户勾选+排序结果）
│
├─ 边条窗口层  Views/ToolSidebarWindow（核心，~2100 行）
│     实例池 / 收起展开 / 拖拽吸附 / 滑动动画 / 自动收起
│
└─ 模块执行层（按 Kind 分流）
      palette → ToolPaletteWindow 系浮窗（抽号/计时/秒表/时钟）
      page    → 主窗口导航到对应工具页
      action  → Services/TeachingActions.cs（讲台动作）
      panel   → VolumeWindow / VolumeMixerWindow + VolumeFlyoutGroup 联动
                + Services/Audio/*（手写 Core Audio）+ BrightnessService
```

**数据流一句话**：布局页把用户拼好的 id 顺序写进 `AppSettings.SidebarModuleIds` 并 `Save()` → `ToolSidebarWindow.ApplyModules()` 按清单重建工具按钮 → 点按钮按 `Kind` 分流执行。

---

## 3. 模块定义层：一个 id 走天下

- 每个 `SidebarModule` 只带 `Id / Name / ShortName / Glyph / Kind / Page / Note`。**id 同时是设置键**（palette 类就是工具 id）。
- `Kind` 四种（`SidebarModuleKinds`）：
  | Kind | 行为 |
  |---|---|
  | `palette` | 置顶小浮窗（ToolPaletteWindow），不占主界面 |
  | `page` | 拉出主窗口并跳到那一页 |
  | `action` | 讲台动作：按一下就干活，不外跳、不抢焦点 |
  | `panel` | 贴边浮窗（音量/亮度），在边条挨着的那一侧滑入 |
- **加新模块 = 在 `All` 里加一行**，其余层全自动（布局页库列表、侧边栏按钮生成都读这份清单）。只有需要「老用户也能看到」时才要抬 `SidebarModulesRevision` 走一次性迁移。

### 已推翻的旧方案（别改回去）
- 「最小化全部窗口」按钮已删：「回到桌面」（Shell COM `ToggleDesktop`）与它效果完全一样。
- 早先把音量/亮度做成**边条内嵌一栏**（`VolumePanel.*` / `VolumeColumn`）：会把边条越撑越宽、贴上下边时 112 高塞不下竖滑块 —— 2026-09-26 推翻，统一成**独立浮窗**。

## 4. 边条窗口层（ToolSidebarWindow）关键设计

### 4.1 不是单例，是「一条边一个实例」的池

```csharp
Dictionary<string, ToolSidebarWindow> _pool;   // 键 = left|right|top|bottom
```

- 起因（2026-09-27）：左右两边要能**同时**显示 → `"both"` 拆成 left + right 两条实例。
- 每条实例的边存在实例级 `readonly _edge` 里，**不读设置** —— 否则两条会贴到同一条边。
- 建过的实例**留着复用**：切边/换模式只是显隐，不反复建窗。唯一的调度口 = `SyncInstances()`（该显示的建/显，不该的 `HideSelf()`）。
- 静态入口（`ShowSidebar` / `HideSidebar` / `ApplySetting` / `ApplyModules` / `IsSidebarVisible`…）全部是**遍历 `_pool`**。

### 4.2 两种模式共用同一套吸附逻辑

| 模式 | 允许的边 | 位置存哪 |
|---|---|---|
| 贴靠 `dock` | 只有左/右（可选「左右两边」） | `SidebarEdge` |
| 自由 `free` | 左/右/上/下四条都能吸 | `SidebarFreeEdge`（无 both） |

- ⛔ **自由 ≠ 浮在屏幕中间**。侧边栏永远吸在某条边上；曾误实现过「不吸边拖哪停哪」版，已整体删除。
- 两模式差别只剩两处：`DesiredEdges()`（允许哪几条边）和 `DockToNearestEdge()`（松手把边存进哪个设置）。

### 4.3 位置 = 比例，不是像素

沿边位置存 `SidebarPosRatio`（0~1），好处：
- 换分辨率/换屏幕不丢位置；
- **左右两条共用同一个 ratio** → 「两边位置一致」是天然成立的，不需要同步坐标；
- 双边拖动时横向锁死（不许换边，一换就把"两边都有"拖成单边），每帧 `FollowPartner()` 把 Y 甩给对面；**故意不落盘**（每帧写 settings.json 会顿），松手统一存。

### 4.4 状态机与动画：一切竞态靠「代次」作废

- 收起(20×110) ↔ 展开(92×450) 两态；滑动 = 按帧 `DispatcherQueueTimer` 逐帧 `Move`。
- **`_slideEpoch` 代次计数**：每次状态变化 +1，让还在跑的旧动画立刻作废。没有它就会出现「展开到一半点收起，动画后续帧又把窗口挪回去」（按钮跑到左上角事故的根因）。`_collapseEpoch` 同理。
- 展开/收起都有从贴边滑入/滑出的方向感（贴右从右往左）。

### 4.5 自动收起与「压住」：必须会自己过期

- `SuppressAutoCollapse` 的实现是**时间戳**（设 true = 压到 15 秒后为止，到点自己恢复），不是普通 bool —— 早先的 bool 版出过「一旦设了 true 没人回来清，侧边栏永远不收」的真 bug。
- 音量浮窗开着期间，`VolumeFlyoutGroup.HoldSidebar()` 用 5 秒循环定时器**持续续期**；浮窗全关才 `ReleaseSidebar()`。
- 需要压住的场景：浮窗开着、确认面板活着、按住型动作进行中。

### 4.6 尺寸：竖条靠常量，横条靠算式

- 竖条厚度/长度是常量（92/450）；**横条（贴上下边）宽度必须按内容算**（`PlannedSize` 取工具行与底排行中更宽者）—— 2026-09-27 底排加第五颗时忘改算式，最后一颗只剩半个字。
- 底排五颗改成**逐颗开关**后，尺寸处处按**可见颗数**摊：
  - 竖条高度增量 `FooterDipFor(n) = round(94 × n / 5)`。**94 是经验增量不是真实高度**（450 基数里已含标题+留白），⛔ 别改写成 `n×44`（会和基数重复计算，面板凭空长一截）。
  - 横条高度：n>0 取 112，n==0 取 72（只剩工具行）。
  - 参与 `PlannedSize` / `ExpandedLimits` / `ApplyScrollLimit` / `ApplyEdgeLayout` **四处**，漏一处就是「少一颗空一块」或「按钮被裁」。

### 4.7 拖拽与吸附

- 鼠标**按下即拖**（收起态抓手）；拖动用屏幕坐标换算，松手 `DockToNearestEdge()` 找最近的边吸附；双边模式跳过「找最近边」，保持本边只更新 ratio。
- 展开态**不能拖**（会和点按钮打架）。

## 5. 配置页层（SidebarLayoutPage）：自绘拖拽

### 5.1 交互模型
左 = 模块库卡片，右 = 按真实侧边栏比例画的预览条。加模块 = 拖进去或点一下；排序 = 在预览里拖；移除 = 拖出预览或格子上的 ×。

### 5.2 为什么不用系统 DragDrop，而是 Pointer 捕获 + ghost 替身
要支持触摸、要「预览里的模块实时让位」、要 ghost 跟手变形 —— 系统 drag drop 给不了。ghost 卡片跟着指针跑，落点画「空档」提示框，松手才真正改 `_ids` 落位。

### 5.3 触摸/鼠标是两套启动规则（必须的，别为「统一」改回去）
- 鼠标：按下即拖（没有「滑动页面」手势冲突）。
- 触摸：**按住 ≥400ms 且手指定住（150ms 静止判定）**才接管；闸门期位移 >12px 判定「想滚」，手势还给 ScrollViewer。
- 「定住」不是手感微调，是**正确性**：让 ScrollViewer 松手（`CancelDirectManipulations`）在 DM 线程落地要几十毫秒，手指还在滑时接管必被抢走捕获。

### 5.4 拖动中数据不变
`_tiles` 列表顺序在拖动过程中**保持不变**，让位靠每行 `TranslateY`（+145ms 动画），松手才 `MoveTo()` 改真数据 —— 顺序一乱让位就对不上。

## 6. 面板浮窗（音量/亮度）与联动

- `VolumeWindow`（类名是历史遗留）一个窗口伺候两个模块（`Target.Volume/Brightness`）：音量 = 数值+竖滑块+静音+展开；亮度 = 第一颗键换自动亮度、无二级浮窗。
- 「展开」再弹横向**合成器**浮窗（`VolumeMixerWindow`，会话行按 pid 增量复用，拖拽不断）。
- 联动核心 `VolumeFlyoutGroup`（纯静态）：
  1. **一起收**：任一浮窗失焦 → 延迟 220ms 查 `GetForegroundWindow()`，焦点还在任一浮窗就不收 —— 否则点「展开」的瞬间主浮窗失焦即收，合成器成孤儿；
  2. **按住边条**：`HoldSidebar()` 5 秒续期压住自动收起；两个都关了（`OnAnyHidden`）才放手并补一次收边条；
  3. 贴哪条边由浮窗自己按 `EdgeGeometry` 算（双边模式固定挂右边）。
- 轮询节奏刻意不同：音量 1500ms（Core Audio 内存调用，微秒级）、亮度 3000ms（WMI 一次十几~几十 ms，自动亮度还要起 `powercfg` 子进程），**读数都走后台线程**，否则 UI 周期性卡顿。

## 7. 讲台动作（TeachingActions）三原则

1. **能调系统 API 就调 API，模拟按键只当兜底**：回桌面用 Shell COM `ToggleDesktop`，调不到才模拟 Win+D；模拟按键的 `INPUT` 结构在 x64 必须补齐到 40 字节（少了整批拒收 err=87）。
2. **关窗口一律优雅关闭**（`WM_CLOSE` = 点 ×），绝不硬杀 —— 老师没保存的 PPT 不能没。
3. **动作做完把焦点还回去**，别打断全屏 PPT。⚠️ 例外：「要先问一句」的动作（「关全部」的两步确认）**先不还焦点**，否则确认面板会被系统当「点了别处」关掉 —— 用户看到的就是「按钮没反应」。

其他要点：
- 「关全部」= 先 `EnumWindows` 攒清单（连最小化的也算，但排除系统壳/工具窗/自家窗口）→ 只**点数报数**，用户在确认面板按红键才真关（`ConfirmPending`）。
- 「关前台」找目标窗口：前台是干净应用窗就用它，否则按 **z 序**从上往下找第一个合格的（自家窗口置顶，「我们下面那个」正是用户在用的）。⚠️ 别用「上次记下的前台」—— 别的程序抢一下焦点就被记错人（2026-09-25 事故）。

## 8. 持久化与迁移

| 设置键 | 含义 | 备注 |
|---|---|---|
| `SidebarModuleIds` | 侧边栏上模块的 id 顺序 | 布局页唯一产出 |
| `SidebarFooterHidden` | 底排**被关掉的**按钮 key（空=全显） | 记「关掉的」是故意的：以后加新按钮老用户默认能看见；key（fold/pin/reset/hide/openapp）属存档格式，⛔ 别改字面量 |
| `SidebarEdge` / `SidebarFreeEdge` / `SidebarMode` / `SidebarPosRatio` | 贴哪边 / 模式 / 沿边位置 | |
| `SidebarModulesRevision` | 模块清单版本号 | 加新模块必须 +1，`EnsureNewSidebarModules()` 一次性把新 id 补进用户清单 —— 防「用户删掉的模块每次启动被塞回来」 |

老存档的 `SidebarFooterEnabled`（总开关）只做一次性迁移：false → 五颗塞进 Hidden，然后拨回 true 当「已迁」标记（不拨回会每次启动重迁，把用户打开的又按回去）。

## 9. 加一个新模块的操作清单

1. `Data/SidebarModule.cs` → `SidebarModules.All` 加一行（id / 名称 / 短名 / Glyph / Kind；action 类插在该组最前）。
2. **抬 `AppSettings.SidebarModulesRevision`** 并在 `EnsureNewSidebarModules()` 里补对应分支（否则老用户看不到）。
3. `Kind=action` → `TeachingActions.Begin()` 加 case；需要确认的在 `AsksFirst` 登记。
4. `Kind=panel` → 新浮窗窗口 + 注册进 `VolumeFlyoutGroup` 同款联动（或独立组）。
5. 布局页与侧边栏按钮**自动**出现，无需改 UI 代码。
6. 若动底排按钮 → 同步改尺寸算式四处（§4.6）。
7. 验证：编译 → `--page=<tag>` 冒烟 → 侧边栏真机手测（拖拽/触摸类**必须 Nick 手测**，注入式测试床不可信）。

## 10. 已知约束与坑（速查）

- ⛔ 换边/换模式必须走 `ApplySetting()` 重建，别只 `SnapToSetting()`（`_edge` 实例级只读，会「一贴就弹回原边」）。
- ⛔ `SidebarLayoutPage` 的拖拽补间（Height Storyboard + 逐帧位移）是**刻意写法**：整格位移的行会不重画（视觉消失），别改 TranslateTransform。
- ⛔ 音频层枚举会话时绝不 `Marshal.ReleaseComObject(control)` —— 同一 RCW 的不同接口视图，释放会让 `ISimpleAudioVolume` 变死引用（读得到写不进）。
- ⚠️ 自动亮度：内屏 WMI、外接 dxva2/DDC-CI 兜底；没环境光传感器时按钮置灰；读不到就如实说，不假装 0%。
- ⚠️ 改任何存档 json 前先 `taskkill`（应用退出时整份写盘会抹掉手改）。
- 待实测项：触摸拖拽真机手感、横条 n==0 时 72 高的实际渲染（当时按计算值定的，未实测）。
